# Contributing

Спасибо, что уделили время участию в проекте.

## Прежде чем начать

1. Откройте issue с описанием проблемы или фичи, чтобы согласовать подход до написания
   кода.
2. Если изменение затрагивает слой провайдеров, TUI или формат конфига, сначала
   напишите короткий дизайн. Крупные рефакторинги, меняющие устройство компонентов,
   требуют письменной спецификации, а не патча.

## Рабочий процесс

```bash
git clone https://github.com/ra1phdd/zev-go.git
cd zev-go
make check
```

- Ветка от `main` с осмысленным именем (`feat/add-anthropic-provider`).
- Одно логическое изменение на коммит; тесты пишутся первыми (TDD).
- Перед пушем прогоните `make check`: и `golangci-lint run --fix`, и
  `go test ./... -race` должны быть чистыми.
- Откройте PR с описанием, что и зачем изменено, со ссылкой на issue.

## Стиль кода

Авторитетные правила — в [AGENTS.md](../../AGENTS.md) и [CLAUDE.md](../../CLAUDE.md).
Основное:

- Vertical slices с ports and adapters. Бизнес-логика живёт в
  `internal/entities/*/service`; `cmd/*` только связывает зависимости.
- Интерфейсы объявляются на стороне потребителя и остаются маленькими.
- Никаких однострочных обёрток и абстракций «на будущее».
- Функции с более чем тремя аргументами принимают именованную структуру параметров;
  `context.Context` — всегда первый аргумент и никогда не поле структуры.
- Ошибки оборачиваются через `fmt.Errorf("...: %w", err)`; ошибки не игнорируются.
- Комментарии к документации начинаются с имени сущности.
- Весь пользовательский текст проходит через `internal/core/i18n`.

## Тесты

- Новое поведение требует теста. Для нескольких сценариев используйте table-driven тесты.
- Юнит-тесты должны быть быстрыми и изолированными; integration-тесты помечаются build
  tag `integration`.
- Провайдеры тестируются через `httptest` — сетевых вызовов в тестах нет.

## Документация

- Документация двуязычная: `docs/en/` и `docs/ru/`, имена файлов в верхнем регистре,
  языковая шапка и перекрёстные ссылки строго внутри одного языка.
- Оба языка обновляются в одном коммите.
