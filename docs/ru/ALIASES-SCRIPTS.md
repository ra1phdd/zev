# Управляемые алиасы и скрипты

Алиасы и скрипты — локальные именованные сущности в `~/.zev`. При обработке запроса Zev ищет их до отправки оставшегося natural-language запроса в LLM. Встроенные команды CLI имеют приоритет над именами сущностей.

## Имена и хранение

Имя должно соответствовать `[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}` и не совпадать с именами встроенных команд, например `query`, `run`, `script`, `history`, `setup`, `update`, `version`, `help`, `tool`. Коллизии между хранилищами алиасов, скриптов и built-in команд отклоняются.

| Путь | Содержимое | Защита |
|---|---|---|
| `~/.zev/aliases` | YAML-метаданные алиасов версии 2 | Приватный файл `0600`, кооперативная блокировка, атомарная замена |
| `~/.zev/scripts` | YAML-метаданные скриптов версии 2 | Приватный файл `0600`, кооперативная транзакционная блокировка |
| `~/.zev/script_files/` | Тела скриптов | Каталог `0700`; новые тела `0700` в Unix |
| `~/.zev/.<name>-scripts.lock` | Межпроцессная блокировка хранилища скриптов | Постоянная идентичность; не удаляйте и не заменяйте |

Формат metadata строгий и версионированный. Неизвестные поля, неправильные типы, дубли аргументов, некорректные имена, invalid UTF-8, управляющие символы и слишком большие документы отклоняются. Текущие readers принимают только версию 2; legacy migration выполняется до открытия хранилища.

## Алиасы

Алиас — argv-safe шаблон одной простой команды. Поддерживаются отдельные placeholders:

- `{{.arg1}}`, `{{.arg2}}`, … — позиционные значения;
- `{{.args}}` — все переданные значения.

Нумерованные placeholders должны идти без пропусков. При подстановке аргумент заключается в POSIX single quotes и остаётся одним shell-словом, даже если содержит пробелы или shell-метасимволы. В самом template запрещены пайпы, перенаправления, command substitution, кавычки, обратный слеш, glob, assignments, shell control words и повторный запуск shell, например `sh -c`. Для shell-синтаксиса используйте скрипт, а не пытайтесь кодировать его в алиасе.

Порядок аргументов можно описать metadata. Обязательные аргументы должны предшествовать необязательным; отсутствие обязательного значения и лишние значения отклоняются до выполнения. Максимум — 32 аргумента metadata; длина имён и описаний ограничена.

Примеры:

```bash
zev alias add dps "docker service ps {{.arg1}} --no-trunc"
zev dps my-service
zev alias list
zev alias last recent
zev recent
zev alias edit dps
zev alias remove dps
```

`zev --print NAME ...` раскрывает алиас, не выполняя его. `--json` выводит обычную machine-mode схему команды. `-h` для алиаса показывает его локальную справку и не вызывает LLM. Для `alias remove` принимаются псевдонимы `rm` и `delete`.

## Скрипты

Скрипт содержит имя, неизменяемый record ID, описание, упорядоченные аргументы metadata и относительный путь тела внутри `script_files`. Путь должен быть относительным и нормализованным, без traversal и платформенного абсолютного синтаксиса. Компоненты путей приложения и конечный файл не могут быть symlink; файлы должны быть обычными и с одной жёсткой ссылкой.

Создание и редактирование доступны через редактор или ограниченный non-interactive ввод:

```bash
zev script create deploy "Деплой приложения"
zev script create deploy --body-file deploy.sh
zev script create deploy --body-stdin
zev script edit deploy
zev script show deploy
zev deploy staging
zev script remove deploy
```

`script show` читает точное зарегистрированное тело и не запускает его. Query machine mode не печатает скрипты автоматически; используйте явную команду `script show`. Для `script remove` принимаются `rm` и `delete`.

Редактор получает приватную временную копию. После успешного сохранения Zev повторно проверяет исходную запись, путь, файловую identity и content hash до публикации. Устаревший редактор получает конфликт вместо перезаписи новой версии. Ошибка или отмена оставляет зарегистрированный скрипт без изменений и удаляет временный каталог.

## Публикация и восстановление

Изменения алиасов используют кооперативный read-modify-write lock и атомарную замену в том же каталоге. Создание, замена и удаление скрипта координируют публикацию метаданных и тела приватным подписанным journal в `.scripts-journal`. Recovery проходит явные фазы и проверяет SHA-256 перед публикацией staged-файла. Так различаются сбой до публикации и уже выполненная публикация.

Это не транзакция над всеми файлами: ошибка fsync каталога после rename может означать, что новая версия уже видна, но её сохранность после сбоя неизвестна. Если операция вернула `ErrCommitted`, перед повтором проверьте текущее состояние. Zev не создаёт резервные копии для безопасного стирания и не обходит пользовательские копии.

## Генерация metadata

`--generate-description` и `--generate-arguments` — явные opt-in сетевые операции. Для обычного CRUD они не нужны. В интерактивном режиме Zev показывает destination, payload и сообщает, локальный endpoint или удалённый; `y` или Enter подтверждают, `n` отклоняет, Esc отменяет. Сгенерированные поля проверяются теми же правилами metadata; ошибка генерации поля выводит предупреждение и не делает сущность невалидной. Перед генерацией тело скрипта ограничивается по размеру.

Не включайте credentials в description, template, тело скрипта или prompt. Запрос провайдеру может раскрыть выбранную сущность настроенному endpoint.

## Выполнение и безопасность

Алиасы и скрипты выполняются напрямую при вызове по имени; настройка `command_execution_mode` на них не влияет. До выполнения Zev применяет централизованную security policy и одноразовый grant:

- алиасы проверяются ограниченным анализатором shell;
- скрипты считаются opaque code и требуют подтверждения в `security.mode: auto`;
- grant привязан к точной команде или байтам скрипта, аргументам, policy, identity рабочей директории и фильтрованному окружению;
- изменение тела, policy, cwd, окружения или входа делает grant недействительным;
- grant используется один раз, для повтора нужна новая оценка.

`security.mode: bypass` пропускает permission confirmation в заданной области, но не создаёт sandbox. Host-команда может менять файлы, обращаться к сети и читать ресурсы, доступные пользователю. Для управляемых дочерних процессов фильтруется окружение и выполняется очистка процессов; детали в [Безопасности](SECURITY.md). Runtime Windows для этих путей намеренно ограничен; кросс-компиляция ничего не доказывает.

## Совместимость и тестирование

Текущий формат — версия 2. Поддерживаются только migration inputs выпущенных форматов; dev-снимки не являются контрактом совместимости. Проверки включают codec/validation metadata, рендеринг алиасов, lock/cancellation хранилищ, path security, конфликт устаревшего редактора, durability/recovery journal и CRUD через собранный бинарник. Запуск:

```bash
make test
make test-race
make test-e2e
```

`make test-e2e` — black-box gate и может требовать deployment prerequisites, перечисленные в документации. См. [Конфигурацию](CONFIGURATION.md), [справочник CLI](CLI.md), [Безопасность](SECURITY.md) и [Разработку](DEVELOPMENT.md).
